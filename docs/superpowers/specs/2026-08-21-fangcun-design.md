# 方寸（Fangcun）桌面应用设计规格

- 日期：2026-08-21
- 状态：已确认
- 目标版本：MVP 0.1
- 首发平台：macOS

## 1. 产品概述

方寸是一款本地优先的个人桌面工作台，用于集中管理常用书签、提示词、每日待办和随笔记录。它首先服务于单个用户的日常科研与开发工作，同时保持清晰的模块边界和可迁移的数据结构，为后续开源及跨平台扩展保留空间。

产品名称为“方寸”，英文与仓库标识统一使用“Fangcun”和 `fangcun`。

## 2. 设计目标

MVP 应满足以下目标：

1. 用户可以导入浏览器导出的通用 Bookmark HTML，并保留原有文件夹层级。
2. 用户可以粘贴网址，由应用尝试获取网页标题、简介和图标，然后完成收藏。
3. 用户可以创建、编辑、搜索、标记和复制提示词。
4. 用户可以通过日期查看和管理每日 Todo，并书写当天的自由随笔。
5. 所有核心数据保存在本地，无需注册、登录或部署服务器。
6. 应用能够在 macOS 上安装和运行；退出重开后数据完整保留。
7. 代码结构适合开源，后续可以补充 Windows 和 Linux 支持。

## 3. 非目标

MVP 不包含以下能力：

- 账号、云同步和多人协作；
- 浏览器扩展；
- AI 模型调用、提示词变量模板和提示词版本历史；
- 富文本编辑器、附件管理和图片笔记；
- 重复 Todo、提醒通知和复杂日程事件；
- 高级统计、数据看板和插件系统；
- Mac App Store 发布。

这些能力可以在 MVP 稳定且真实使用需求明确后单独设计，不在首版预埋未使用的复杂实现。

## 4. 技术方案

### 4.1 技术栈

- 桌面框架：Tauri 2
- 前端：React + TypeScript
- 构建工具：Vite
- 样式：Tailwind CSS
- 图标：Lucide
- 本地数据库：SQLite
- 单元与组件测试：Vitest + React Testing Library
- 端到端测试：WebdriverIO Tauri Service
- macOS 分发：`.app` 与 DMG

### 4.2 选择理由

Tauri 使用操作系统 WebView 渲染前端，不随应用携带完整浏览器运行时，适合轻量本地工具。React 和 TypeScript 便于构建可维护的模块化界面，也有利于未来吸引开源贡献者。SQLite 适合单用户、本地优先和结构化数据场景，并支持事务与版本化迁移。

Python 不进入 MVP 主进程。未来若增加 AI 分类、批量文本处理或科研脚本能力，可以通过独立进程或服务边界接入，避免首版同时维护两套运行时。

## 5. 系统架构

应用划分为四层：

1. **界面层**：页面、可复用组件、导航、筛选器和编辑器，仅处理展示与用户交互。
2. **业务服务层**：书签导入、网址标准化、标签管理、自动保存、Todo 迁移和聚合搜索等用例。
3. **数据访问层**：按领域提供 Repository 接口，集中执行 SQLite 查询和事务，页面组件不得直接拼接 SQL。
4. **Tauri 系统层**：窗口、原生文件对话框、文件读写、外部链接打开、网页元数据获取和应用数据目录管理。

React 前端与 Tauri 系统层通过明确的命令或插件接口通信。Rust 代码保持精简，只承担需要系统权限、安全边界或不适合在 WebView 中完成的工作。

### 5.1 建议目录边界

```text
src/
  app/                 # 启动、路由、主题和全局错误边界
  features/
    home/              # 首页聚合
    bookmarks/         # 书签页面、服务和数据访问
    prompts/           # 提示词页面、服务和数据访问
    journal/           # 日记、Todo 和日历
    settings/          # 设置、备份和恢复
    search/            # 跨模块搜索
  shared/              # 通用组件、类型和工具函数
src-tauri/
  src/commands/        # 网页元数据、备份恢复等系统命令
  migrations/          # SQLite 迁移
tests/                 # 端到端测试与测试夹具
```

每个功能模块公开少量稳定接口，内部页面、服务和 Repository 可以独立修改和测试。

## 6. 导航与界面结构

### 6.1 主导航

采用固定左侧边栏，保持极简命名：

- 首页：房屋图标；
- 书签：书签图标；
- 提示词：文本对话图标；
- 日记：打开书本图标；
- 设置：齿轮图标，固定在底部。

图标全部使用 Lucide 线性图标，不混用 Unicode 符号。

### 6.2 全局操作

- `Command + K`：打开全局搜索；
- 快速添加：根据当前页面创建书签、提示词或 Todo；
- 页面切换后保留该页面的筛选条件和滚动位置；
- 支持浅色、深色和跟随系统三种主题。

首版优先保证信息层级、可读性和交互一致性。颜色、圆角、阴影和动效在核心流程可用后再统一优化。

## 7. 功能设计

### 7.1 首页

首页默认显示本地时区中的今天：

- 左侧展示今日 Todo，可新增、勾选和排序；
- 右侧展示今日随笔；
- 顶部可以切换前一天、后一天或返回今天；
- 提供进入完整日记页面的入口。

首页不创建独立数据，只聚合日记和 Todo 数据。

### 7.2 书签

书签页面提供：

- Bookmark HTML 导入；
- 粘贴网址并手动添加；
- 自动获取标题、网页描述和站点图标；
- 自定义标题、描述、文件夹和标签；
- 按文件夹、标签和关键词筛选；
- 列表和卡片两种展示方式；
- 在默认浏览器中打开网址；
- 编辑和删除。

书签文件夹用于保留导入层级，也允许用户后续创建和调整。书签标签与提示词标签完全独立。

### 7.3 提示词

提示词页面提供：

- 标题、正文和备注；
- 自定义标签；
- 收藏状态；
- 按标题、正文、备注和标签筛选；
- 一键复制正文；
- 自动保存；
- 编辑和删除。

正文按纯文本保存，完整保留换行和特殊字符。MVP 不提供富文本工具栏、变量替换和模型运行按钮。

### 7.4 日记

日记页面采用左侧月历、右侧内容的布局：

- 选择任意日期；
- 查看并编辑该日 Todo；
- 新增、完成、取消完成和拖动排序；
- 将未完成 Todo 移动到今天、明天或指定日期；
- 编辑该日自由随笔；
- 自动保存。

随笔按纯文本保存，并兼容 Markdown 文本，但 MVP 不提供 Markdown 预览和富文本格式化。

### 7.5 设置

设置页面包含：

- 主题选择；
- 当前应用数据位置只读展示；
- Bookmark HTML 导入入口；
- 创建完整备份；
- 从备份恢复；
- 应用版本和开源仓库信息。

## 8. 数据模型

所有业务实体使用 UUID 文本主键，为未来同步与数据合并保留稳定标识。时间戳使用 UTC ISO 8601；日记日期使用用户本地时区的 `YYYY-MM-DD`。

### 8.1 核心表

| 表 | 关键字段 | 约束与说明 |
|---|---|---|
| `bookmark_folders` | `id`, `parent_id`, `name`, `sort_order` | 支持任意层级；同级名称可重复 |
| `bookmarks` | `id`, `url`, `normalized_url`, `title`, `description`, `favicon_path`, `folder_id` | `normalized_url` 唯一 |
| `bookmark_tags` | `id`, `name`, `color` | 标签名在书签域内不区分大小写唯一 |
| `bookmark_tag_links` | `bookmark_id`, `tag_id` | 联合主键 |
| `prompts` | `id`, `title`, `content`, `notes`, `is_favorite` | 正文不能为空 |
| `prompt_tags` | `id`, `name`, `color` | 标签名在提示词域内不区分大小写唯一 |
| `prompt_tag_links` | `prompt_id`, `tag_id` | 联合主键 |
| `daily_entries` | `id`, `entry_date`, `content` | 每个日期至多一条随笔 |
| `todos` | `id`, `todo_date`, `content`, `is_completed`, `sort_order` | 每个日期独立排序 |
| `settings` | `key`, `value` | 仅保存非敏感应用设置 |

除关联表和设置外，业务表均包含 `created_at` 和 `updated_at`。

### 8.2 网址标准化

重复检测使用 `normalized_url`，规则为：

- 主机名转为小写；
- 删除 URL fragment；
- 删除 HTTP/HTTPS 默认端口；
- 统一根路径末尾斜杠；
- 保留路径、查询参数及其顺序；
- 不主动删除跟踪参数，以避免错误合并两个实际不同的地址。

原始 URL 始终保留用于展示和打开。

## 9. 核心数据流程

### 9.1 HTML 书签导入

1. 用户选择本地 HTML 文件；
2. 应用以文本方式读取并使用隔离解析器解析文件夹和链接；
3. 展示文件夹数、书签数和重复项预览；
4. 用户选择跳过重复项或用导入内容补全缺失字段；
5. 在一个数据库事务中写入文件夹、书签和关联数据；
6. 展示成功、跳过和失败统计，并允许复制失败摘要。

导入不得执行 HTML 中的脚本或加载远程资源。

### 9.2 手动添加书签

1. 用户粘贴 URL；
2. 应用校验仅允许 `http` 和 `https`；
3. Tauri 后端以受控超时和响应大小限制获取网页元数据；
4. 用户可以修改自动获取的标题和描述；
5. 保存时执行重复检测；
6. 元数据获取失败时仍允许使用 URL 和域名作为默认信息保存。

### 9.3 自动保存

- 提示词和随笔在内容变化后 500 毫秒执行防抖保存；
- Todo 的新增、完成、排序和迁移即时保存；
- 编辑器显示“保存中”“已保存”或“保存失败”；
- 页面切换、窗口失焦和应用退出前尝试刷新待保存内容；
- 保存失败时保留编辑器内容，并提供重试操作。

### 9.4 全局搜索

`Command + K` 打开搜索面板，同时查询书签、提示词和日记内容。结果按模块分组，每组限制初始展示数量，并提供进入对应页面查看全部结果的入口。

MVP 使用参数化 `LIKE` 查询。Repository 接口不暴露具体搜索实现，未来可以升级为 SQLite FTS5，而无需修改页面调用方式。

## 10. 错误处理与数据完整性

- 所有 SQL 使用参数化查询；多记录写入使用事务；
- 数据库迁移有单调递增版本，只允许按顺序执行；
- 导入失败不得留下半完成的数据；
- 网络请求设置连接与读取超时，并限制响应正文大小；
- 网页元数据解析失败不得阻止保存网址；
- 表单错误在字段附近显示，系统级错误使用非阻塞通知；
- 删除操作要求确认，并明确显示将被删除的对象；
- 全局 React 错误边界防止单个页面异常导致整个窗口空白；
- 日志不得记录提示词正文、日记内容或完整浏览历史。

## 11. 备份与恢复

完整备份使用带时间戳的 `fangcun-backup-YYYYMMDD-HHMMSS.zip`，包含：

- SQLite 数据库；
- 已缓存的网站图标；
- 备份格式版本和应用版本清单。

生成压缩包前，应用通过 SQLite 在线备份机制创建一致性快照，不直接复制仍在写入的数据库文件。

恢复流程：

1. 用户选择备份文件；
2. 应用校验压缩包结构和备份版本；
3. 自动创建当前数据的安全备份；
4. 关闭数据库连接并替换数据；
5. 重新打开数据库，运行必要迁移；
6. 成功后刷新应用，失败则恢复原数据。

MVP 不自动定时备份，以免未经用户选择写入额外目录。

## 12. 隐私与安全

- 核心功能离线可用，数据默认只写入系统应用数据目录；
- 应用不包含遥测、账号和远程数据库；
- 只有自动获取网址信息和打开网址需要联网；
- 网页元数据命令只允许 HTTP/HTTPS，并限制重定向次数、下载大小和超时；
- Tauri capability 仅授予实际使用的文件、对话框、SQL 和外部打开权限；
- 导入文件只读，未经用户明确操作不得覆盖原文件。

## 13. 测试策略

### 13.1 单元测试

- Bookmark HTML 文件夹与链接解析；
- URL 校验、标准化和重复判断；
- 两套标签关系互不干扰；
- Todo 排序和跨日期迁移；
- 自动保存防抖与失败重试；
- 备份清单校验。

### 13.2 组件测试

- 书签与提示词表单校验；
- 文件夹和标签筛选；
- 日历日期切换；
- Todo 完成状态和排序交互；
- 自动保存状态提示；
- 全局搜索结果分组。

### 13.3 端到端测试

至少覆盖三条核心路径：

1. 导入 HTML 书签，确认文件夹和重复处理正确；
2. 创建提示词、添加标签、搜索并复制正文；
3. 为指定日期创建 Todo 和随笔，退出重开后确认数据仍存在。

## 14. MVP 验收标准

满足以下条件后，MVP 可以进入日常试用：

- macOS 可通过 DMG 安装并正常启动；
- 无网络时可以使用除网页元数据获取和打开链接外的全部核心功能；
- 三条核心端到端流程通过；
- 退出重开后数据完整，自动保存无静默丢失；
- HTML 导入异常不会污染已有数据；
- 完整备份能够在干净数据库上恢复；
- 界面在浅色和深色主题下无关键内容不可见或无法操作；
- README 能说明开发环境、启动方式、数据位置和构建命令。

## 15. 实施顺序

实现按以下里程碑推进，每个里程碑都应保持应用可运行：

1. 项目骨架、导航、主题、数据库迁移和测试基础设施；
2. 书签数据模型、手动添加、HTML 导入和重复处理；
3. 提示词编辑、独立标签、搜索和复制；
4. 日历、日记、Todo、自动保存和首页聚合；
5. 全局搜索、备份恢复、错误处理和 macOS 打包；
6. 真实使用反馈驱动的 UI 统一优化。

详细任务拆分、文件清单和测试步骤将在本设计通过用户审阅后，通过独立实施计划确定。
